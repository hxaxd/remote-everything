# 安全模型

Remote Everything 面向**单用户自托管**设计：一个人、一台云服务器、一台 Windows 电脑、若干自己的手机。部署多实例互不影响。在采用本方案前，请确认你接受以下边界。

## 防护层

- 公网唯一入口是 Caddy 443 端口，**全局强制 mTLS**：没有有效客户端证书的连接在 TLS 层就被拒绝。
- 两类客户端证书由两套 CA 签发，权限不同：
  - **引导证书**（内置在 App 里）：按指纹被 Caddy 限制为只能访问设备注册接口 `/__remote_everything_enroll/*`。
  - **设备证书**（审批后逐设备签发）：可访问应用接口，且必须再带 Bearer 控制令牌。
- 新设备接入必须**人工审批**：设备出示 8 位审批码，管理员在服务器上核对后签发证书。这是整个体系的核心安全边界。
- 吊销即时生效：删除证书文件、重建信任链、reload Caddy。
- Windows 侧本地控制接口 `POST /__local_remote_control`：仅监听 loopback、验证本地令牌（常量时间比较）、只接受 POST、限制请求体大小，公网路径被 Caddy 显式 403。
- 云端服务以最小权限运行：三个无登录权限的系统用户、systemd 沙箱（`ProtectSystem=strict` 等，见 `server/*.service`）。

## 明确的弱点（知情接受）

- **服务器 root 可冒充任何已审批设备**。设备 mTLS 私钥由服务端生成（经 PKCS#12 下发），因为部分手机的硬件密钥无法用于 TLS 客户端认证（见 AGENTS.md 事故教训）。防护依赖「服务器是你自己的」。
- **控制令牌烧进每个客户端安装包**（BuildConfig 注入），所有已审批设备共享同一令牌。令牌泄露+一张有效设备证书=完全控制。单用户场景可接受；多设备分令牌是未来的多租户方向。
- 注册请求创建时提交 p12 口令，服务器在审批前将其明文保存在状态目录（`0600`，审批后立即擦除）。该窗口期内服务器 root 可读。
- `/__remote_everything/open/<id>` 与状态页在 mTLS 之内不再要求 Bearer（有意设计：状态页是电脑离线时的兜底错误页，且所有客户端都持有令牌，加验无实际收益）。
- 本仓库历史版本中，连接参数曾以明文存在于源码并被 AI 编码助手处理过；如你的部署曾外发过配置文件，请轮换控制令牌与引导证书。
- **卓易通兼容模式**：在没有可用 AndroidKeyStore 的环境（如卓易通容器），设备证明密钥与包裹密钥以软件形式保存于应用私有目录，不再具备硬件绑定；注册界面会明示「兼容模式」。其余平台不受影响。
