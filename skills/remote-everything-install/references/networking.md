# 网络拓扑

一台电脑 = 一个安装实例 = 一个节点。移动客户端按 `installation_id` 保存多个 Profile，手动切换。
多台电脑部署详见 [multi-computer.md](multi-computer.md)。

## 同网或远程组网

运行节点和 LAN 入口。入口动态端口写入 `lan.json` 与二维码；防火墙仅允许移动设备所在 LAN 网段或组网接口访问该端口，节点端口保持 loopback。

异地且没有公网服务器时，先与用户对齐是否已有远程组网：有则复用，没有则推荐免费虚拟组网 Tailscale 并指导建立。验证目标移动客户端与节点均在线、节点地址稳定且入口端口可达后按 LAN 形态部署，不运行 FRP 或公网网关；项目不维护组网产品本身。

## Linux 公网服务器

```text
移动客户端 ── HTTPS/mTLS ── 443入口 ── 网关状态端口 ── 节点隧道端口
移动客户端 ── HTTPS邀请 ─── 443入口 ── 网关配对端口
节点 ───────── WSS/443 ───── 443入口 ── FRPS端口
```

四个服务器内部端口均从 `server.json` 读取且只监听 loopback。公网只新增既有 443 流量；22 仅用于既有管理。网关初始化一次生成安装 ID、控制令牌和 FRPS token，并用独立隧道 CA 签发 frpc 客户端证书；它们不能复用设备 CA。整套隧道材料只留在服务器：节点只接收安装 ID 与控制令牌，不接收任何证书或隧道材料。

节点与公网服务器同机时同样按公网形态部署：bootstrap bundle 本机传递即可，FRPC 连接本机 443，经反向代理回环到本机 FRPS；全部组件端口都是动态 loopback，互不冲突。两侧各自使用独立的项目副本与 `.runtime/`，运行记录、状态与日志互不相干，移除任一侧不影响另一侧。
