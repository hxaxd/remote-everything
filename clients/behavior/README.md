# 统一行为测试

三个客户端不是靠"看着像"统一，而是靠这份**共享 fixture + 每端消费它的测试**统一。

```
fixtures/
├── errors.json        线协议里每一个拒绝码 → 客户端该说的那句话的 key
├── nodes.json         两个网关的 /nodes 答案 → 合并后的节点行与选中的路径
├── paths.json         地址分类、当前声明更新与路径断开/恢复 → 该走哪条
├── catalog.json       一个 catalog 答案 → 那一页该显示什么状态
├── cadence.json       刷新与等待的节奏 → 三端同一种耐心（数字活在各自代码里，测试把它们钉在这儿）
├── message-keys.json  三端共用的一套用户可见字符串 key → 每端 MessageKeys 常量集、资源键集都与它逐一相同
├── web-app-prefs.json 每个应用的 Web 宿主偏好（屏幕方向、标识）的取值词表与默认值 → 三端同一套词、同一个默认
├── web-session-scope.json 网关、节点与应用 → 独立网页存储的稳定标识
├── tls.json           公开测试证书、主机名、有效期和固定值 → 接受或拒绝（不含私钥）
└── wire-cases.json    线协议严格性用例（跨字段规则、取值集、长度/字符限制）→ 三端各自用严格解码器跑同一个判据
```

规则：

- **key 是契约**，句子里不是。每端在自己的资源里把同一个 key 渲染成自己的语言与措辞；`MessageKeys`（各端一份，同名同值）是这些 key 的唯一出处。`message-keys.json` 钉住这套 key 本身：各端测试断言自己的常量集 == fixture、资源键集 == 常量集。
- 每端在**自己的测试**里加载这些文件、断言自己的核心层得出同样的结论（同一句话的 key、同一行、同一条路径、同一个页面状态）。任何一端改了映射而没改 fixture，它的测试就会失败。
- fixture 只描述**结论**，不描述实现：语言不同、类型不同、写法不同都没关系，结论必须一致。
- 新增一个拒绝码、一个状态、一句话：先在 fixture 里出现，再三端各自实现，最后三端测试都过——这是"统一"这个词在这个仓库里的唯一含义。

行为约定（写进代码、也写进这里的承诺）：

- **原生客户端界面**：配对按“扫码/粘贴 → 确认节点与网关 → 设备名称 → 加入”的连续表单组织，输入和确认信息同时可见，失败在原处提示。节点列表采用“名称在左、路径/状态在右”的卡片；节点页面将当前路径放在标题下方。设置依次为语言、外观、连接、关于，语言与外观展开为选项行。应用网页占满当前应用窗口，退出回到原节点。各平台保留原生导航、控件与系统视觉效果；iOS 的配对和设置使用系统弹层。
- **忘记一个网关**：删除它的身份、节点记录、待批准配对与节点缓存；保留其应用的独立网页存储。网页存储按网关、节点、应用区分，不作为网关准入凭据；重新配对同一网关后可继续使用原应用数据。
- **应用网页会话**：按网关 origin、nodeId、appId 分隔。Android 使用独立持久化 WebView Profile，iOS 使用独立持久化 WKWebsiteDataStore；HarmonyOS 同时只持有一个隐私浏览上下文，关闭页面及下载后加密保存该应用的 Cookie，等待旧组件销毁并清空隐私网页存储与 Cookie 后才能恢复下一应用。这层隔离保护不同应用已保存的浏览器状态，不改变网关按节点授权的规则，也不将不可信网页变成独立的操作系统安全沙箱。
- **应用网页首次显示**：打开、刷新和崩溃重建时，地址准备与新网页首帧之间均用不透明的当前主题色加载层覆盖；主网页和弹窗采用同一规则。首次内容绘制（FCP）后撤掉加载层，失败则显示主题色错误页或关闭失败弹窗。普通页面导航与历史返回不重新启用首次显示遮挡；保留网页自身的颜色和无背景页面的白色默认画布。Android 与 iOS 观察网页绘制性能事件，Android 还等待像素可绘制的确认；HarmonyOS 使用同一事件的原生回调。
- **每个应用的 Web 宿主偏好**：一个应用的方向与标识（`web-app-prefs.json` 钉住词表与默认值）按 `nodeId/appId` 记忆，只影响那一个应用的下一次打开；默认是跟随系统 + 移动标识，且从不写入任何线协议字段。
- **未决配对的窗口**：窗口由配对应答的 `pending_expires_at` 决定；读不懂时严格拒绝该应答（`wire-cases.json`）。前台自动检查待批记录，两次检查之间间隔 5 秒。每次检查的进度至少显示 1.5 秒，请求更慢时继续显示；批准结果立即生效。同一网关的手动重试复用正在进行的检查及反馈。后台暂停，回前台立即检查。临时断网保留记录；批准、明确拒绝、到期或主动放弃后结束，不另设轮询总时长。
- **配对与控制操作**：原生端全局只保留一个进行中的配对申请。退出页面可继续等待；开始新一轮添加（包括新传入的邀请）会取消上一份申请。待批凭据独立保存，取消、拒绝、过期或被取代时只删除该临时凭据，所有已完成连接继续可用；新申请获批后才替换对应网关的正式连接。旧申请晚到的兑换或批准结果不能重新登记或覆盖新申请。临时故障保留当前申请供自动或手动重试。四端直接停止应用，忘记连接仍需确认；应用接口的停止请求预算 30 秒，其他请求 10 秒。应用控制独立轮询至稳定状态，间隔由 1 秒递增至 5 秒，总等待约 60 秒；命令响应丢失后只读状态，不跨路径重发命令。已停止的应用只能显式启动，启动中的应用在网页入口等待就绪，停止中的应用不能打开。
- **未决窗口内的再次扫码**：新扫码或外部传入邀请视为新一轮添加，先取消当前申请，再展示新邀请；当前页面的重试继续使用同一申请的凭据和兑换参数，不重复消费邀请。

各端入口：

| 端 | 测试位置 |
|----|----------|
| Android | `clients/android/app/src/test/java/com/remoteeverything/behavior/BehaviorFixturesTest.kt` |
| HarmonyOS | `clients/harmony/entry/src/ohosTest/...`（同一批 fixture，同一批断言） |
| iOS | `clients/ios/RemoteEverythingTests/BehaviorFixturesTests.swift` |

在 `clients/behavior/` 执行 `npm ci`、`npx playwright install chromium`、`npm test` 可运行宿主与浏览器回归；已有 Edge 时可设置 `BROWSER_CHANNEL=msedge`。`clients/harmony/tests/controllers.cjs` 擦除 ArkTS 类型后执行生产控制器，验证交错请求、凭据更换、独立控制和持久化逻辑，不替代设备测试。

`web-capabilities.html` 供测试应用托管，覆盖弹窗返回、上传与取消、权限、下载、方向和存储；`tests/web-capabilities.cjs` 验证其中可自动化的网页操作，设备权限与原生选择器仍需在设备上验收。
